## 0. 这版改了什么

用户澄清了三点，直接改变了整份需求的重心：

| 澄清 | 影响 |
| --- | --- |
| 用户就是我自己，这是能力提升 + DIY 极客产品 | 删除定价/订阅/B 端/渠道/竞品商业分析；放宽可靠性、外观、认证要求；**把"能学到什么"提升为一等目标** |
| 语音 = 预置录音，手机端手动选择播放 | 砍掉麦克风、双向音频、TTS；设备只需存几段 WAV + 接收播放指令，实现成本降一个数量级 |
| 当前是概念原型 | 不做 IP67、不做模具、不做认证、不追 45 天续航；**以"验证四件事"为验收** |

被降级或删除的需求（保留在归档里备查）：多用户共享、B 端 API、订阅体系、保险合作、注塑量产、SRRC/进网许可排期、竞品商战分析。

## 1. 项目定位

### 1.1 一句话

> **给自己自行车装一个"防盗 + 定位 + 会喊话"的联网盒子，顺便把嵌入式、无线通信、传感器、机械结构这四块能力走一遍真项目。**

它同时是两件事：

- **一个自用工具**：车停楼下，被动了手机能知道，能看位置，能远程放一段录音吓人。
- **一个练手载体**：覆盖"传感器 →  MCU → 无线 → 云 → 手机"的完整链路，且每一环都有真实约束（功耗、误报、电源瞬态、金属遮挡）。

### 1.2 成功标准（与商业产品完全不同）

| 维度 | 商业产品 | 本项目 |
| --- | --- | --- |
| 成功判据 | 用户留存、误报率 < 0.2 次/周 | **装上去自己愿意一直开着** |
| 成本 | BOM 压到极限 | 单件 ≤ ¥300 可接受 |
| 外形 | 要好看、要品牌感 | 能装、不晃、不进水即可 |
| 时间 | 赶窗口 | 8–10 周业余时间 |
| 失败容忍 | 低 | **高，过程本身是产出** |

### 1.3 能力地图（这个项目真正想练到的）

按"投入产出比"排序，这四块是核心收益：

| 能力 | 在本项目中的具体形态 | 可迁移性 |
| --- | --- | --- |
| **传感器信号处理** | IMU 50 Hz 采样、时域特征、阈值整定、混淆矩阵 | 极高，所有 IoT 设备通用 |
| **低功耗嵌入式** | FreeRTOS 任务划分、休眠调度、外设电源域控制 | 极高 |
| **无线通信与协议** | 4G Cat.1 AT 指令、MQTT、断线重连、LWT | 高 |
| **电源完整性** | 锂电充放、升压、大电流瞬态、brownout 定位 | 高，硬件工程师的分水岭 |
| **机械与结构** | 参数化建模、3D 打印、减震密封 | 中高 |
| **全栈联调** | 设备 → broker → Home Assistant → 手机 | 中 |

> 一句话取舍：**优先做"判定算法 + 电源"，其次做"通信 + 定位"，最后做"外壳 + App"**。因为前两者的经验最难通过看教程获得，后两者可以找到大量现成方案。

## 3. 三个仍然成立的判断

### J1：误报是唯一的死因

自己用，容忍度比商业产品高，但同样有临界点：**半夜被自己装的设备吵醒两次，你就会把它关掉。** 而且你的使用场景更复杂——白天停公司楼下、晚上停小区、周末停骑行驿站，每个场景的"正常震动"都不一样。

对策（按性价比排序）：

1. **影子模式**：第一周只记录、只推送、不响。用真实数据校准阈值。（见 prototype-plan §7.4）
2. **分级响应**：轻碰 → 不动作；持续 → 本地短提示；高危 → 才吼。
3. **车轮信号兜底**：车轮在转 = 有人在推车，这个判断比任何震动阈值都可靠。
4. **自己挪车要能豁免**：BLE 近场自动撤防，或手机点一下"我在挪车"。

### J2：本地闭环优先于云端闭环

车在地下车库、在电梯里、在被塞进面包车时，4G 都可能没信号。但**贼就在车边上，喇叭是唯一还能起作用的东西**。

所以：判定与警报必须在设备本地完成，云端只负责"让人知道"和"让人能插手"。断网时喇叭照样要响。

### J3：语音的作用是"让人犹豫 3 秒"

预制录音的价值不在"沟通"，在于**制造"车主在附近 / 车被盯着"的心理压力**。选一段语气对的声音，比追求音质重要得多。

因此：不需要双向对讲、不需要实时音频、不需要麦克风。**手机上点一下、设备响一段，就够了。**

## 7. 关键设计权衡

### 7.1 判定策略：规则优先，模型靠后

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 单阈值（震度 > X 就报） | 10 行代码 | 误报爆炸 | ✗ |
| **规则 + 时间窗积分 + 多信号投票** | 可解释、好调、省电 | 需要人工整定 | ✅ **首选** |
| 决策树 / 随机森林（导出 C） | 表达力强 | 需要数据量，难调 | 数据够了再说 |
| TinyML（1D-CNN） | 上限最高 | 训练、部署、功耗都费劲 | 最后考虑 |

理由：**规则能让你理解"为什么误报"**，模型只会告诉你准确率。对一个以学习为目的的项目，可解释性比 2% 的召回重要得多。

### 7.2 功耗：原型阶段不优化，但要留接口

原型阶段用 2×18650（约 6800 mAh）跑 2 周，足够。真正要提前做的是：

- 把"什么时候醒、醒来干什么"设计成**可配置的调度表**，而不是写死在代码里。
- 4G 模组用**定时连接**而非常驻（每 10 min 一报）。
- IMU 用**硬件中断**唤醒，别轮询。

> 一个真实经验：**先让设备待机 2 周不炸，再去抠 µA。** 顺序反了会在电源管理上耗掉整个项目周期。

### 7.3 通信：Cat.1 + GNSS 二合一

| 方案 | 结论 |
| --- | --- |
| **Air780EG（Cat.1 + GNSS）** | ✅ 单模组，省 UART、省天线、省调试 |
| Air780E + 独立 GNSS | 多一颗模块，接线复杂，不划算 |
| NB-IoT | 省电但带宽低、时延大、不支持持续音频（也不需要），生态弱 |
| ESP32 直连 WiFi | 只在有 WiFi 时有效，马路上没用 |
| 蓝牙 + 手机中继 | 手机不在车边就废了，不满足需求 |

> 选型时确认三件事：**支持 MQTT over TCP**、**有 GNSS 天线接口**、**AT 指令文档是中文的**。

### 7.4 语音：为什么确定用方案 A

你已明确"预制录音 + 手机选播"。把另外两条路记录下来，避免以后又纠结：

| 方案 | 研发量 | 主要障碍 | 结论 |
| --- | --- | --- | --- |
| **A 预制录音 + MQTT 触发** | 低（1–2 天） | 无 | ✅ 已定 |
| B 给设备打电话（VoLTE） | 中 | 物联网卡**普遍禁语音**，需普通 SIM 或语音卡 | ✗ |
| C 实时音频流（WebRTC） | 高 | 需要麦克风、编解码、服务器带宽 | ✗ |

方案 A 唯一要注意的是**音频文件怎么进设备**（见 prototype-plan §5.2）：原型阶段烧录 LittleFS 即可。

### 7.5 定位：车架是最大的敌人

- 金属车架对 GNSS 是屏蔽体。**原型阶段先外置天线**，验证"能定位"，再做车内布局。
- 冷启动 30–90 s，热启动 5–15 s。做"定时热启动"保持星历。
- 地库/楼道基本无解。**产品承诺要改成"带你到楼下"，而不是"精确到米"。**
- 位移检测优先用 GNSS 位移，但要注意静止时的坐标漂移（加平滑与滞回）。

### 7.6 为第二曲线预留（唯一一个"必须现在就做对"的决策）

码表模式的高功耗与防盗的长待机是矛盾的。V1 只要在这几项上留余量，未来就不用重新开板：

| 项 | 最小够用 | 建议预留 |
| --- | --- | --- |
| MCU | ESP32-S3 已足够 | ✅ 不用动 |
| Flash/PSRAM | 8 MB / 8 MB | ✅ 不用动 |
| 电池 | 3400 mAh | **5000 mAh 以上** |
| GNSS | 1 Hz 输出 | 选支持 1 Hz 连续输出的模组 |
| BLE | 配网 | 保留 BLE 中心+外设能力（ESP32 自带） |
| 存储 | 无 | 加一片 SPI Flash（8 MB，¥3）存轨迹 |

> 说白了：**多花 ¥15 买块大电池和一片 Flash，省掉未来一次重画板。**

### 7.7 外壳：3D 打印就是终态，不用想注塑

- 用 **OpenSCAD 参数化**，改管径出模型，比重画图快得多。
- 材料 **PETG**（好打、耐候）或 ASA（抗 UV，但翘边）。
- 内衬 **2 mm TPU/EVA**，既减震又防刮漆。
- 固定用**不锈钢扎带**，不打孔、可拆、不伤车。
- 防水靠**硅胶垫 + 螺纹生料带 + 充电口塞子**，不追求 IP67。
- 注意**散热**：4G 模组贴导热垫到外壳内壁，夏天实测温度。

### 7.8 自用的合规边界

- 插 SIM 卡上网：物联网卡需**实名认证**，正常购买即可。
- 不涉及 SRRC 型号核准（那是生产销售才需要的），但**不要让设备发射干扰信号**。
- 装在车上拍摄/录音？本项目没有摄像头，音频是"播放"不是"录制"，边界清晰。
- 自己车上装定位器，法律上没有障碍；**别装到别人车上**（这是常识，但写下来）。

## 11. 附录

### 11.1 术语

- **影子模式**：判定逻辑照常运行并上报，但不触发喇叭，用于收集真实误报数据。
- **brownout**：电压跌落导致 MCU 复位。
- **TTFF**：Time To First Fix，首次定位时间。
- **LWT**：MQTT 遗嘱消息，设备掉线时由 broker 代发。
- **PSM/eDRX**：蜂窝省电模式。

### 11.2 与商业化版本的主要差异

| 维度 | v0.1 商业化 | v0.2 本项目 |
| --- | --- | --- |
| 用户 | 多用户、B 端 | 只有自己 |
