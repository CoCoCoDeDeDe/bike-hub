## 当前形态

**一体机**：锁体、电路、电池、喇叭全部装在一起，固定在车架后部，锁环绕后轮。

```
车架 ──┬── 一体化锁体 + hub ──┬── 锁环（绕后轮）
       │                      ├── 机械应急钥匙孔
       │                      ├── 车轮霍尔（预留）
       │                      └── 3 针磁吸触点 ── 模块化车灯（独立供电）
       └── M5 水壶架孔固定
```

固件侧对应 [firmware/README](../firmware/README.md)，硬件侧的决策依据见 [需求分析 §7](requirements.md)。

### 关键约束（来自需求分析）

| 约束 | 原因 | 出处 |
| --- | --- | --- |
| 外壳不能是金属 | 屏蔽 4G/GNSS 天线 | 本文 H-M-09 |
| 承力件必须是金属 | 3D 打印件扛不住剪切 | [分析](requirements.md#7-关键设计权衡) |
| 应急钥匙孔不可省 | 电池耗尽要能骑车 | [分析](requirements.md#7-关键设计权衡) |
| 锁态信号来自锁舌，不是"锁在不在" | 后者可伪造 | [分析](requirements.md#7-关键设计权衡) |

## 已知缺口（记录在案）

| 缺口 | 后果 | 补齐方式 |
| --- | --- | --- |
| 没有车轮霍尔 | 锁着车被**平稳推走**时，振动可能低于阈值，不触发告警 | 加霍尔后，`guard` 把"轮子在转"作为独立告警条件 |
| 没有 GNSS 辅助定位 | 地下车库失联后只能报最后位置 | 见 [原型方案 V3](prototype-plan.md#12-实验与验收清单) |
| 没有后备电源 | 主电池被拔后无法告警 | 需要时加小容量电池 + 掉电检测 |

固件侧对应的扩展点见 [firmware/README](../firmware/README.md)，代码结构已经为这些缺口留好了接入位置（结构体加字段、任务表加一行）。
